# Cat SNS App 仕様書

最終更新: 2026-09-01

## 1. サービス概要

猫の画像のみ投稿できるSNS。

一般的なSNSのアカウント単位の投稿に加え、1人のユーザーが複数匹の猫を登録し、それぞれの猫ごとに独立したマイページと投稿履歴を持てることを特徴とする。

## 5. 投稿仕様

- 投稿主体は「猫」
- 投稿時に、投稿者となる猫を1匹選択する
- 1投稿につき最大4枚まで画像を添付できる
- 同じ投稿内に写っている複数の猫をタグ付けできる
- 投稿に付与できる情報
  - 本文
  - ハッシュタグ
  - メンション
- 位置情報は初期仕様では扱わない
- 投稿できる画像は猫が写っている実写画像のみ
- 投稿時に画像認識モデルまたは画像認識系プラグイン / APIを利用して投稿可否を判定する

### 5.1 画像判定ルール

投稿可:
- 猫だけの写真
- 猫と人が一緒に写っている写真
- 猫と犬など他の動物が一緒に写っている写真
- 猫がかなり小さく写っている写真

投稿不可:
- 猫のイラスト
- AI生成の猫画像
- 猫のぬいぐるみ
- 猫の死骸
- 虐待画像
- 強い流血表現
- 強い怪我の表現

画像判定の具体的なモデル・サービス・判定閾値・例外処理は今後決定する。

## 6. ユーザーと猫プロフィール

### 6.1 ユーザー

- 1ユーザーにつき1つのユーザーアカウントを持つ
- 1ユーザーは複数匹の猫を登録できる
- ユーザーは猫プロフィールの管理者として扱う
- SNS上の投稿者として前面に出るのはユーザーではなく猫

### 6.2 猫プロフィール

- 各猫は独立したプロフィールページ（猫用マイページ）を持つ
- 猫ごとに公開 / 非公開を設定できる
- 猫がSNS上の投稿主体となる
- 猫ごとに投稿一覧を表示できる
- フォロー対象はユーザーではなく猫とする
- 1ユーザーが複数匹の猫を管理できる

猫プロフィール項目:
- 名前
- アイコン
- 性別
- 誕生日
- 猫種
- 毛色
- 飼い主ユーザー

持たせない項目:
- ヘッダー画像
- 年齢
- 性格
- 一言プロフィール
- お迎え日

年齢については誕生日から必要に応じて算出可能とする。

## 7. フォロー仕様

- フォロー対象は猫のみ
- ユーザーアカウント自体はフォロー対象にしない
- フォロー関係は「ユーザーが猫をフォローする」形で保持する想定
- ホームタイムラインは「おすすめ」と「フォロー」のタブ切り替え式とする
- フォローしている猫が1匹以上いる場合のみ「フォロー」タブを表示する
- フォローしている猫が0匹の場合は「フォロー」タブ自体を表示せず、「おすすめ」のみ表示する
- 「フォロー」タブにはフォローしている猫の投稿を表示する
- 「おすすめ」タブには未フォローを含むおすすめ投稿を表示する
- おすすめロジックの詳細は今後決定する

## 8. UI / UX方針

- XまたはInstagramのUI/UXを参考にする
- SNSとして馴染みのある操作感を優先する
- 猫プロフィールを「もう1つのアカウント」のように扱える体験を差別化ポイントとする
- タイムライン上では猫名・猫アイコンを投稿者情報として前面に表示する
- 飼い主ユーザー情報は猫プロフィール内などで補助的に表示する

## 9. 検索仕様

初期版の検索対象:
- 猫の名前
- 猫種
- ハッシュタグ

ユーザー名は検索対象に含めない。
投稿本文の全文検索は初期版では実装しない。

## 13. SNSインタラクション仕様

### 13.1 いいね
- いいねは1種類のみとする
- ユーザーは投稿に対していいねできる

### 13.2 コメント
- 投稿にコメントできる
- コメントへの返信を許可し、スレッド形式に対応する

### 13.3 保存
- 投稿をブックマーク保存できる
- 保存一覧は本人のみ閲覧可能とする

### 13.4 シェア
- MVPではアプリ内リポストは実装しない
- OS標準の共有機能等を利用した外部共有には対応する

### 13.5 非公開猫
- 猫プロフィールを非公開に設定できる
- 非公開猫へのフォローは申請制とする
- 飼い主ユーザーがフォロー申請を承認または拒否できる
- 承認済みユーザーのみ非公開猫の投稿を閲覧できる

### 13.6 通知
MVPで以下の通知に対応する。
- 猫がフォローされた
- 非公開猫へのフォロー申請
- フォロー申請の承認
- 投稿へのいいね
- 投稿へのコメント
- コメントへの返信
- メンション

### 13.7 ブロック / ミュート
- ブロック機能を実装する
- ミュート機能を実装する
- 詳細な適用範囲は今後決定する

### 13.8 通報
以下を通報対象とする。
- 投稿
- 猫プロフィール
- ユーザー

通報理由、審査フロー、管理画面仕様は今後決定する。


## 14. 画像判定フロー

- 画像判定は複数モデルに分けて実施する
- 少なくとも以下の2系統に分離する
  - 猫画像判定モデル
  - 安全性 / モデレーション判定モデル
- 投稿前にすべての画像判定を完了させる
- 1投稿内の最大4枚すべてが投稿条件を満たした場合のみ投稿を確定できる
- いずれか1枚でも判定NGの場合、そのままでは投稿できない
- 判定中は投稿確定ボタンを無効化する、または判定完了待ち状態を表示する
- 判定NGになった画像は、理由をユーザーに分かる形で表示する
- モデルの一時エラーやタイムアウト時は投稿を確定せず、再判定できるようにする

### 14.1 猫画像判定モデルの責務

以下を判定する。
- 実写の猫が画像内に存在するか
- 猫が小さく写っている場合も許可対象とする
- 人や犬など他の被写体が一緒に写っていても許可する
- イラストは拒否する
- AI生成画像は拒否する
- ぬいぐるみなど実在の猫ではない被写体は拒否する

### 14.2 安全性 / モデレーション判定モデルの責務

以下を拒否対象とする。
- 猫の死骸
- 虐待
- 強い流血
- 強い怪我
- その他、サービス上不適切と判断する重大な暴力表現

### 14.3 投稿確定条件

投稿画像ごとに以下の条件をすべて満たす必要がある。
1. 猫画像判定: OK
2. 実写判定: OK
3. AI生成 / イラスト / ぬいぐるみ判定: NG対象に該当しない
4. 安全性判定: OK

すべての画像が条件を満たした時点で投稿可能とする。
